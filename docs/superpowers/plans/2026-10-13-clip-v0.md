# Clip v0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `npx clip` in a project folder turns the best moment of the latest Claude Code session into a 30-second square MP4, rendered locally.

**Architecture:** Five pure modules in a pipeline (`transcript` → `tests` → `score` → `redact` → `render`), each a function over plain data with its own tests, joined by a thin `cli.ts`. Rendering copies the four hand-built HyperFrames scenes from `templates/` into a temp project, injects a `ClipData` JSON, and shells out to `npx hyperframes render`.

**Tech Stack:** TypeScript 5, Node ≥ 22, `node:test`, esbuild (CLI bundle to `bin/clip.cjs`), HyperFrames CLI via `npx`, `gh` CLI for the public-repo check.

**Spec:** `docs/superpowers/specs/2026-10-13-clip-v0-design.md`

## Global Constraints

- Node ≥ 22; `engines.node: ">=22"`.
- Package name `@atpes/clip`, bin name `clip`, MIT.
- Output video 1080×1080, total length between 24 and 34 s.
- Every string that reaches the render passes through `redact()`; nothing is uploaded anywhere.
- Fixture transcripts are synthetic: the real line shape, invented content, no real user text.
- Layout mirrors agent-undo: `src/`, `tests/*.test.js` (run against `dist/`), `scripts/build.mjs`, committed `bin/`.

## Review Focus

1. A transcript line that is not valid JSON (Claude Code writes partial lines on crash) → skipped, not a crash. Test in Task 2.
2. A `tool_result` whose `tool_use_id` was never seen (truncated or compacted session) → ignored. Test in Task 2.
3. A test command whose output has the summary **twice** (e.g. `npm test` re-running a nested runner) → the last summary wins. Test in Task 3.
4. An episode with more than 8 test runs → the clip shows 8 and "+N more runs"; total length still ≤ 34 s. Test in Task 7.
5. A cwd whose `gh` lookup fails (no remote, not logged in) → treated as not public, stop with the `--private-ok` hint, not a stack trace. Test in Task 5.

### Task 2: Transcript parser

**Files:**
- Create: `src/transcript.ts`, `tests/transcript.test.js`, `tests/fixtures/red-green.jsonl`, `tests/fixtures/no-tests.jsonl`, `tests/fixtures/broken-lines.jsonl`

**Interfaces:**
- Produces:
  ```ts
  type FileEdit = { kind: 'write'|'edit'|'shell'; file: string; added: number; removed: number; at: string };
  type TestRun  = { kind: 'test'; command: string; exitOk: boolean; output: string; at: string };
  type Commit   = { kind: 'commit'; hash: string; subject: string; at: string };
  type Event = FileEdit | TestRun | Commit;
  type Episode = { index: number; prompt: string; startedAt: string; endedAt: string; events: Event[] };
  function parseTranscript(path: string): Episode[];
  function sessionsFor(cwd: string, home?: string): string[]; // newest first
  ```
  `TestRun.output` is raw stdout+stderr; Task 3 parses it. Test commands are detected by `TEST_COMMAND_RE = /\b(npm (run )?test|pnpm test|yarn test|bun test|vitest|jest|node --test|pytest|go test|cargo test)\b/`. A commit event comes from a Bash call whose command contains `git commit` and whose stdout matches `/\[\w[\w\/-]* ([0-9a-f]{7,})\] (.+)/`.

- [ ] **Step 1: Write the fixtures**

`red-green.jsonl`: 2 prompts. Episode 1 is chat only. Episode 2: a `Write` of `src/clone.ts` (toolUseResult `{filePath, structuredPatch:[{lines:["+a","+b"]}]}`), an `Edit` of `src/snapshot.ts` (`+3 -1`), a Bash `node --test tests/` with `is_error:false` and stdout `ℹ tests 9\nℹ pass 8\nℹ fail 1\n✖ copy fallback honours the size guard (1ms)`, a second Bash `npm test` with stdout `ℹ tests 9\nℹ pass 9\nℹ fail 0`, a Bash `git commit -m x` with stdout `[main abc1234] feat: thing`. Timestamps 2 minutes apart. One sidechain line in the middle that must be ignored. `no-tests.jsonl`: one prompt, two edits, no test command. `broken-lines.jsonl`: `red-green` plus a line `{"type":"assist` (cut off) and a `tool_result` with an unknown `tool_use_id`.

### Task 4: Episode scoring and selection

**Files:** Create `src/score.ts`, `tests/score.test.js`

**Interfaces:**
- Consumes: `Episode`, `parseTestOutput`.
- Produces:

### Task 6: Clip data

**Files:** Create `src/clipdata.ts`, `tests/clipdata.test.js`

**Interfaces:**
- Consumes: `ScoredEpisode`, `redactDeep`.
- Produces:
  ```ts
  type TestState = { clock: string; passed: number; failed: number; total: number; failingNames: string[]; isNew?: boolean };
  type ClipData = {
    repo: string; date: string; prompt: string; minutes: number;
    files: { file: string; kind: 'new'|'changed'; added: number; removed: number; clock: string }[];
    codeLines: string[];            // up to 4, from the first Write's patch, ≤ 90 chars each
    tests: TestState[];             // ≤ 8, plus
    moreRuns: number;
    commits: { hash: string; subject: string }[];
    redCount: number;               // number of red runs
  };
  function buildClipData(e: ScoredEpisode, meta: { repo: string; home: string; root: string }): ClipData;
  ```
  `clock` is `mm:ss` since the prompt. `files` keeps at most 3, by lines changed. `tests` keeps the first 8 runs that have a summary; `moreRuns` is the rest. A run whose summary names a failing test absent from all earlier runs gets `isNew: true`.
